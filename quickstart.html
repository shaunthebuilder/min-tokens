min-tokens · quick guide

It saves tokens so you don't have to think about it.

It's installed and always on. You do essentially one thing.

← the one thing you do

When you see the context warning, type /clear.

⚠ context ~80K — wrap up, then /clear

That's the whole job. Your work is saved automatically the moment before, so /clear starts a fresh, cheap session that already knows where you left off. Use /clear, never /compact.

Why not /compact? Compacting re-reads your entire session to summarize it — that's the expensive thing min-tokens exists to avoid. /clear + the saved state is the cheap path.

Everything else is automatic

  • Turns on by itself in every new conversation — nothing to start.
  • Keeps answers lean and reads your files surgically — full quality on real work, terse on chatter.
  • Saves your project's state at natural stopping points — so the next session skips re-exploring.
  • Warns you only when a session gets large — silent the rest of the time.

Optional — nice, never required

  • If Claude suggests “switch to Sonnet,” change the model in the picker — cheaper for routine work. It never switches on its own.
  • Curious about usage? Type /min-tokens anytime — answers instantly for free, showing your week + the single best next move.

Commands (all optional)

/min-tokensShow context size, this week's usage, and the one best action.free
/min-tokens saveSave project state right now (also happens automatically).
/min-tokens offTurn it off. /min-tokens on brings it back.free

free = answered on the spot without spending any tokens — the command never reaches the model. Only /min-tokens save runs the model, because it summarizes the conversation.

To stop it entirely: /min-tokens off — reversible anytime. Nothing to uninstall.
