01

The plan was fixed.
The spend wasn't.

min-tokens exists because a $20/month Pro plan and an agentic coding habit are on a collision course. The intent was never to make Claude say less — it was to find and remove the token spend that buys the user nothing: idle chatter, re-read context, oversized tool results, and reflexive use of the most expensive model for work a cheaper one handles identically well.

02

The line the plugin
will not cross.

Every subsequent design decision answers to one governing rule, borrowed and sharpened from an external review: every injected token must provably save more than it costs. Economy applies to five things only — and explicitly never to six others.

Economize on
  • Process chatter — status, confirmations, recaps
  • Redundant context — re-reading what's already known
  • Oversized tool results — logs, screenshots, dumps
  • Model overkill — Opus/Fable for Sonnet-shaped work
  • Session lifecycle — letting context balloon past its useful size
Never economize on
  • Thinking, planning, and reasoning depth
  • Deliverable completeness — code, docs, decks, analysis
  • Correctness checks, security, input validation
  • Accessibility basics
  • Any explanation the user explicitly asked for
03

One skill.
Zero touch.

The product surface is deliberately narrow: a single user-visible skill, /min-tokens, backed by hooks that do free local work every turn and only spend tokens when a threshold is actually crossed.

Two registers, one firewall

Chatter (status, confirmations, recaps) is capped at three short lines, no headers, no tool-call narration, no invented abbreviations. Deliverables (code, docs, decks, explanations) are never compressed — full quality, never truncated. When it's unclear which one applies, it's treated as a deliverable.

Zero-token slash commands

/min-tokens, off, and on are answered directly by a UserPromptSubmit hook returning {"decision":"block","reason":"…report…"} — the prompt never reaches the model. Only /min-tokens save spends a turn, because writing state.md requires the model to summarize the conversation.

Context-ceiling warnings

The same hook estimates live context from the transcript on every message and stays silent below 80K. At 80K it prints a one-line soft warning; at 120K, a hard one. Thresholds are overridable via MIN_TOKENS_SOFT / MIN_TOKENS_HARD.

state.md protocol

/min-tokens save writes a compressed-register state file — telegraphic prose, structure kept, every path/command/name exact — so the next session reads ~1–2K tokens of state instead of re-exploring the codebase. Then the user starts a new thread (/clear in the CLI), never /compact. A new thread and /clear cost the same — both begin a fresh context that reads the state file back — but the new thread leaves the prior conversation readable.

Big-file discipline

Large generated files — HTML docs, decks, this whitepaper — are patched with an edit tool, never re-emitted whole for a local change, and never read back immediately after being written. Added after the worst measured offenders turned out to be exactly this workflow.

04

Evolution: v1 to v2.

v1 shipped from the measured ground truth in §01: a plugin absorbing and retiring an older, six-skill sprawl (ponytail), replacing it with one skill, invisible hooks, and a rules block of ~800 tokens. v2 followed a deep external review — a full read of a comparable open-source project, caveman — adopted where the evidence held, rejected where it didn't.

The finding that mattered most

Caveman's own published numbers showed its output-compression skill costs ~1–1.5K input tokens per turn, and a 65% output reduction collapses to just 14–21% session-level savings — because output is a minority of spend. That matched this project's own measurement almost exactly: output is 17.8% of weighted spend, while cache writes (43.1%) and reads (39.1%) together are 82%. The two projects' levers barely overlap. Caveman spends its budget compressing the 18% bucket on every turn; min-tokens spends a comparable one-off, cached at the head of the session, on the 82% bucket.

05

The final product.

A single installable Claude Code plugin — plugin.json, hooks/, scripts/, one skills/min-tokens/ — built, installed, and live-verified: a resumed session comes up with the rules block injected, the old plugin gone, and the context warning firing correctly.

06

Using it well.

Do
  • Let Sonnet be the default; escalate to Opus/Fable deliberately for planning or hard debugging, then step back down
  • Run /min-tokens save at task boundaries, then start a new thread (/clear in the CLI) — never /compact
  • Switch models only at task boundaries — the prompt cache is per-model
  • Read state.md instead of re-exploring the codebase when one exists
  • Cap noisy command output; quote the one decisive error line on failure
Don't
  • Set thinking-token caps to save spend — that is a quality guardrail, not a lever
  • Compress a deliverable — prose, code, decks, explanations stay full quality
  • Re-emit a whole large HTML file for one edit — patch it instead
  • Treat an estimated saving as real — only a measured week-over-week A/B counts
  • Spawn subagents or web-fetches casually — each re-pays the full session baseline

Same thinking. Same quality.
A fraction of the spend.

min-tokens is one plugin, one skill, and a governing rule: every token it spends has to earn its way back.
